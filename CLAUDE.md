# sc

- In this repo, always push after committing (overrides the global no-push rule).
- Don't hardcode a specific case (a named env var, path, host, feature flag) into the script when a config- or data-driven mechanism already exists or fits. Extend the existing mechanism (profile `[dirs]` / `[env]` / `[github]` sections, config `[group]` / `[env.<name>]` tables, a list, a table) so new cases are added as data, not code. If none exists and more than one case is plausible, prefer introducing a small one over special-casing. Example: mounting `$OBSIDIAN_NOTES_DIR` is done via a profile's `[dirs].rw` + `[env].pass`, not a branch in `sc`; Datadog keys for pup are an `[env.datadog]` bundle in config.toml, not a `--datadog` flag.
- User config (`~/.config/sc/config.toml`, `~/.config/sc/profiles/*.toml`) is personal and machine-synced, but edit it directly when a change belongs there — don't print a file for the user to copy-paste. Read it first, keep everything already in it, and say what you changed. Never commit it into this repo (it holds private paths; the repo is public).
- `~/.config/sc` is a symlink into a synced folder. sc bridges the link path so it works inside the sandbox (`docs/symlinked-dirs.md`); if it is still denied, the session predates the bridge — read the realpath instead of concluding the grant is missing.
