# sc

- In this repo, always push after committing (overrides the global no-push rule).
- Don't hardcode a specific case (a named env var, path, host, feature flag) into the script when a config- or data-driven mechanism already exists or fits. Extend the existing mechanism (profile `[dirs]` / `[env]` / `[github]` sections, a list, a table) so new cases are added as data, not code. If none exists and more than one case is plausible, prefer introducing a small one over special-casing. Example: mounting `$OBSIDIAN_NOTES_DIR` is done via a profile's `[dirs].rw` + `[env].pass`, not a branch in `sc`.
- User config (`~/.config/sc/config.toml`, `~/.config/sc/profiles/*.toml`) is personal, machine-synced — you must NOT edit it. When the user asks to change something that belongs there, do NOT write the file. Instead, print the exact, complete file content (the full resulting file, not just the delta) in a code block so the user can copy-paste it. Read the existing file first so the printed version merges cleanly with what's already there.
